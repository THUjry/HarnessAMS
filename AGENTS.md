# AGENTS.md — HarnessAMS (top-level repo)

> Rules for AI agents and human maintainers working in this repo. Read this file before changing anything here. This repo is the entry repo of the HarnessAMS multi-plugin system: plugin index + install guide + compatibility matrix, hosting the aggregate bundle `dsh-harnessams-suite` (in `install_suite/`) and the bundled `LocalDesignExample` environment; the top-level console plugin source lives in `src/index.js`. This repo keeps English-only, self-contained content (no references to files outside the repo).

- Package `dsh-harnessams` / row id `harnessams-top`; aggregate bundle `dsh-harnessams-suite` (pure patch package: its patch explicitly restates every member row — npm dependencies alone do not apply config layers).
- `engines.dsh` locks the verified DSH version; upgrades require re-running the minimal regression before updating `docs/compatibility.md`.
- What the top-level repo does not do: no mirroring of other plugins' sources, no hosting of other plugins' patches, no overriding other plugins' config defaults in its own patch.
- The console plugin (in `src/`) serves a self-contained HTML UI plus JSON APIs via `ctx.webServer.register` under `/harnessams`; remote node checks go through OpenSSH wrapped in `bash -c` with `BatchMode=yes` (credentials stay with the system OpenSSH, never persisted by the plugin); failing checks offer a one-click agent diagnosis prompt.
- Safety by default: destructive operations move paths to the trash folder; the best point is persisted to `bestPoints.json` first.
- Custom web routes are not token-gated by the DSH web server: serve only management UI and static reports on them; never expose credentials or remote-execution surfaces without adding an auth layer.
- Workspace convention (runtime, outside any repo — `LocalDesignExample/` being the checked-in exception): a `harnessams.json` at the workspace root provides fixed paths (`ngspice_cmd`, `pdk_lib`, `trash_dir`); relative values resolve against the config file's directory; the plugin locates it by walking upward from the package and from cwd (bare form, or inside `harnessams-workspace/`).
- Repo layout: console plugin package in `src/` (entry `src/index.js`, plain JS, no build chain; the package also ships `src/assets/` and `src/scripts/` — `PUBLISH.md` holds the must-contain / must-not-contain tarball checks), aggregate bundle in `install_suite/`, starter unit tests in `tests/` (bare `node --test` from the repo root; a directory argument fails on Node 24).
- `src/assets/` holds the **single shared** `plotly.min.js` for the whole HarnessAMSproject tree (plus its THIRD_PARTY_NOTICES). Never add a second copy anywhere under the project; it ships inside the `dsh-harnessams` tarball, and consumers (SmartAnaSim's report generator, `LocalDesignExample/tools/`) discover it by walking up from their own location, via the workspace `plotly_asset` config field, or from a sibling `dsh-harnessams` install under `node_modules/`.
- `LocalDesignExample/` rules: vendored binaries/models stay byte-exact (`.gitattributes` disables line-ending conversion for them); `tools/` holds verbatim copies of the SmartAnaSim pipeline scripts — re-sync them whenever the plugin's `scripts/` change; `harnessams.json` there must keep relative paths (portability across clone locations); `demo1/` and `demo2/` are placeholders until the demo milestones land, and any run outputs under them are gitignored, never committed.
- sky130 closure fact: `combined_models/` alone is NOT a working copy — `corners/*.spice` reference `cells/` models through two levels of relative includes, so the minimal closure is combined_models plus those cells files; copying only combined_models fails with `Could not find include file`.
- Self-contained HTML pages (the console UI, generated reports) have no bundler safety net: one JavaScript syntax error silently blanks the whole page. Keep the per-section try/catch isolation and test-render after edits.
- Commits require an explicit user request or authorization.
