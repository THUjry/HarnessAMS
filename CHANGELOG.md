## [Unreleased]

### Added

- System-first directory access for the add-report dialog (2026-11-26): the add action (toolbar and empty state) now FIRST tries the host's native OS folder chooser — the same dialog the host's add-workspace flow uses — through the new `POST /api/pick-directory` route over the host `directoryPicker` service. A picked folder with exactly one HTML registers it directly (one dialog total); a folder with a choice of HTMLs lands the dialog's one-level listing there; ANY failure — no native picker on web-SSH/headless hosts (the browse backend has no pick), auth, timeout, non-2xx — silently falls back to the self-made listing, and a user cancel does nothing. The listing (`GET /api/browse`) remains the fallback and the in-dialog file picker (the native dialog chooses FOLDERS only, FOS_PICKFOLDERS), and the manual path input is unchanged. The service is read via `ctx.get` without an inject declaration (`src/server/pickdir.js` — a static inject would leave the plugin PENDING in headless compositions), the guarded probe survives the real ctx proxy's undeclared-read throws, and the pick is driven through the CAPABILITY object (`capability().pick`; `service.pick` is undefined — a live first-build defect: the kind probe answered 'native' while the pick returned 503), with a 10-minute abort fence. The same-origin guard blocks of open-local and remote-browse mkdir now share one `sameOriginError` helper. Tests 169 → 172 (the pickdir unit suite including the capability-shape and proxy-throw regressions; the route harness suite; the client static contract).
- Standalone report registration + the versionless session store (2026-11-26): `register_report` attaches ANY existing local HTML file into the calling session's dashboard (hand-written or third-party pages included — identity, store location and entry fields auto-filled from the caller, a delegated subagent resolving to its topmost user-visible ancestor; validation failures throw), and `gen_sweep_report` gained a `register` parameter (default true; `false` renders without touching sessions.json). `sessions.json` drops its `version` key: the legacy key is ignored on read and healed off on the next write, and compatibility is per-field validation — the read path skips invalid leaves LOUDLY (a single bad report entry, a stale-shape check_params, an invalid report_figs/max_points value, bad session keys) with `warnings[]` riding `GET /api/session-config` and rendering as one warn line at the top of the session branch, while unknown fields survive the read-write roundtrip untouched; the write path keeps the strict PUT-400 contract. Tests 164 → 169 (the D-026 store suite, the register_report group, the gen register:false flow, the six-tool list, the client wiring).
- Remote-root browser enhancements (2026-11-26): the settings-table remote-root picker gained an age column, a refresh button, and folder creation. The listing now carries each directory's mtime — `GET /api/remote-browse` runs `find -L <dir> -maxdepth 1 -mindepth 1 -type d ! -name '.*' -printf '%P\t%T@\n' 2>/dev/null || ls -1p <dir>` and returns `entries: [{ name, mtime }]` (epoch seconds; null when the plain-ls fallback produced the listing, rendered as a dash) — and each row shows "{d}d {h}h ago" with the absolute local time on hover; `-L` and the broken-symlink fallback keep the previous `ls -1pL || ls -1p` semantics verbatim. The current-dir row ends in a square icon-only refresh button (fixed 16px SVG, `.hams-iconbtn`), which re-fetches the level and doubles as the retry after an error. Creating a folder posts the new `POST /api/remote-browse/mkdir` route (the browser's single remote write, open-local-style same-origin fence): an inline form prefilled with `new_folder` validates the name to one printable-ASCII segment (trimmed, 1..64 chars, no "/", no leading ".") client-side and server-side, runs a plain `mkdir` through the dsh-ssh exec funnel (no `-p`, so an existing name errors visibly), and refreshes the listing on success. Tests 150 → 154 (find-TSV parsing, the name fence, remoteMkdir command/errors, the mkdir route suite, and the client static contract).
- System-browser report viewing (2026-11-26): the session Dashboard's Open button launches the report file with the OS default application through the new `POST /api/open-local` route — as a local file, so the report's relative plotly/`SimResults` references resolve offline (the embedded iframe could not serve them past its per-report directory fence and leaned on the CDN fallback). The route is fenced (`src/server/openlocal.js`): viewable-extension whitelist, existing regular file, quoting-safe characters (no `"`/`%`/control chars), plus a same-origin guard on `sec-fetch-site`/`origin` — it is the first route that can trigger an OS process and never accepts executable/script paths. The embedded iframe viewer (iframe + reload + open-in-tab + the stat poll) is retired but fully kept behind the `DASH_SYSTEM_OPEN` flag in `src/client.js` — flip to false to restore it verbatim. Tests 154 → 157 (open-local route/fence/guard suite).
- Hybrid report viewing + on-demand plotly declaration (2026-11-26): the session Dashboard embeds the current report in an iframe again (↻ hard-reload button, `/api/report-stat` mtime/size auto-reload poll, read-only `/harnessams/dash/<sessionId>/<reportId>/…` serving) — the report HEAD's same-origin route step (`/harnessams/assets/plotly.min.js`) renders it offline, closing the gap that had retired the viewer — while the ↗ Open button keeps the OS-default file:// view; the `DASH_SYSTEM_OPEN` flag is retired. The open-local path additionally declares `plotly_url`: when `seedProjectPlotly` reports the copy present (new `present` flag — seeded, refreshed, or already there), the route runs `declarePlotlyUrl`, which adds the declaration surgically on the raw JSON (unknown keys and the settings section round-trip verbatim; a present custom/http(s) value is never touched) — the config stays plotly-free until that first successful click. Tests 150 → 155 (declarePlotlyUrl unit suite; route assertions for present/declared; the launcher-seam rewrite).

### Changed

- Test suite consolidated (2026-11-26, the 2026-11-22 test-compression principles extended to the wave-15..20 deletions): the self-check orchestration flows cut from 14 combinatorial variants to 7 representatives (local spectre green run with the artifact-cleanup assertions folded in, LSF-fail-into-fallback with the diagnosis chain, ssh-fail verdict, in-cluster LSF, remote toolchain pins, the none+remote transfer round trip, the green-run auto-pin tail); the per-command bash -n guard is retired (the wrapper-shape contract stays as the execRemote regex in `server.test.mjs`), the live-progress poll rounds dropped 3 -> 2 (~10 s of real wait), and the `scheduler=local` wait_sec windows dropped 3 s -> 1 s. Reverse-retirement assertions (the 2026-11-25/26 feature deletions they were proving) are gone: `script/`-folder absence x4, the workflow-table gone-strings loops, `report_figs`/`bias_check` legacy-key plants, the retired gen-source shape checks, the prompt-cadence absence lines. Duplicate test-side guards collapse to one canonical surface: the `resolveMachine` unit rejections leave `batch.test.mjs` to `server.test.mjs`, the bare-name pin loop shrinks to one case per key, the template-family second reject and the node-side pre-mult mirror are dropped, and the 32-report-cap error stays single-sited. Tests 158 -> 150, suite 27.3 s -> 21.9 s (PowerShell, bare `node --test`).
- The open-local launcher spawns directly (2026-11-26): `openWithDefaultApp` runs the platform opener (`cmd /c start` / `open` / `xdg-open`) as a direct `node:child_process` argument-vector spawn — the same local-launch pattern as the python probes and the local batch worker — instead of the host ctx.shell seam, whose workspace-write sandbox is unusable on hosts whose workspace contains `%TEMP%` (the Windows ACL restricted-token runner refuses to start, so every execLocal call fails; observed on a web instance whose workspace was `C:\Users\<user>`). ctx.shell stays reserved for in-cluster shell command strings (bsub); the path fence and the same-origin guard are unchanged, and tests inject a launcher through `ctx.openLauncher`.
- `workspace_config.json` no longer materializes the plotly fields at creation (2026-11-26): `plotly_url` and `plotly_asset` are known-but-optional workspace keys (present values — including hand edits — survive every rewrite; `resolveWorkspacePathsAt` reports a null `plotly_asset` when undeclared) and the fresh file carries only `sim_scripts_dir` + `trash_dir`; the `plotly_url` declaration appears after the first successful on-open seed (see Added). Existing projects that already carry the fields from earlier waves keep working unchanged.

### Fixed

- Session-config write-channel unification (2026-11-26): the first-level tab pills wrote through `mutateConfig`, which PUT the closure snapshot unrebased — clicking a session pill right after `gen_sweep_report` registered a report wiped the injected report (the in-memory snapshot only refreshes while the Dashboard sub-view is open). `mutateConfig` keeps the optimistic local flip but now rides the rebased persist channel (`persistConfig`: GET the latest server entry, re-apply the mutator, PUT, adopt the confirmed entry); the mutator contract stays idempotent (applied once to the optimistic snapshot, once to the fresh base). The first-seen tombstone PUT also re-checks the server first — an entry the second writer created between the hydrate GET and the PUT is adopted instead of tombstoned over.

## [0.1.0] - 2026-11-10

Initial release (stage 1 scope).

### Added

- Top-level console plugin `dsh-harnessams` (`src/`): three-tier client UI inside the DSH Web client — global console page (machines over the dsh-ssh host registry, digital assets, disk usage, display settings, first-run onboarding guide), project tier (project = DSH workspace, task store at `<workspace>/.harnessams/tasks.json`), and a task sidebar tab (project overview / Dashboard / Check params / Sim settings). Remote connectivity is fully delegated to @linxin666/dsh-ssh (alias-based, zero gating; per-alias remote roots live in the workspace `harnessams.json` `remote_machines` section). Bilingual zh/en UI throughout.
- Overview health checks: local items directly, remote items through dsh-ssh's `ssh_exec` straight at the configured alias (no borrowed session); columned result tables; failed checks hand off to a diagnosis session (one click, and automatically for remote failures).
- Per-project settings (`project_settings.json`: run mode / machine / remote dir / scheduler / simulator / compute scripts) and a one-click project self-check that walks the whole pipeline under the current settings with no LLM in the flow — RC testbench through the simulator, or the bundled analytic golden replay without one — with pointwise 1% verification and artifact-driven verdicts.
- Six model tools: `batch_submit`/`batch_poll`/`batch_fetch` (generic remote batch channel — LSF queue or ssh foreground on the target host), `gen-sweep-report` (spec-driven Plotly report with per-chart PNG export and session registration), `sim_progress` (local progress-file window), `safe_trash` (workspace trash with fenced restore/purge; deletion never destroys). The analysis pipeline and trash are pure JS; Python is confined to the three scenario families of decision D-003 (`docs/decisions.md`).
- Simulation progress tool cards for the eight simulation tools (`tool.call.toolview`), with a display toggle and read-only progress endpoints.
- Dashboard report viewer: task-registered local HTML reports served read-only with each report's own directory as the boundary, iframe key/nonce reload, auto-refresh while visible; reports render offline from a single workspace-level Plotly copy seeded from the vendored `src/assets/plotly.min.js` (decision D-013).
- Remote batch idempotency guards (compensating the dsh-ssh broken-connection exec replay): LSF submits carry a `.hams_submitted` marker with flock (read-back on replay, write-on-success only); ssh runs carry a `.hams_ssh_done` marker with flock; every remote command is wrapped in a remote `timeout -s KILL` so the deadline always lands.
- Aggregate bundle `dsh-harnessams-suite` (`install_suite/`): one-command install of the first-party plugins (pure patch package that restates every member row).
- Self-check compute assets: `src/scripts/selfcheck/` (`selfcheck_verify.py` + `.mjs`, one JSON contract) and `src/selfcheck/` (the RC generator plus a 36-file analytic 3×3 psfascii golden dataset).
- Workspace config contract: `harnessams.json` is discovered by walking upward (bare form, or inside `harnessams-workspace/`); relative path fields resolve against the config file's directory.
